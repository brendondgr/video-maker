# Plan: edit package — per-scene renders, an OTIO timeline for any editor, a clean project layout

Goal: the AI builds the video's scaffolding (story, scenes, voice, captions, sound). The skill then
hands over an **edit package**: one media file per scene plus an open **OpenTimelineIO** timeline
that opens in DaVinci Resolve, Premiere Pro, Kdenlive, Avid and, through bundled converters,
Final Cut Pro, Shotcut, OpenShot, Lightworks and anything that reads FCP7 XML, AAF or EDL. A person
finishes the video by hand. When the AI changes a scene later, only that scene re-renders and its
file is replaced in place. Project folders get one clear, predictable layout.

Tracking: this file is updated in every commit on the `edit-package` branch. `[x]` = done and
committed, `[~]` = in progress, `[ ]` = not started. Each step below is **one commit**.

| # | Decision | Status |

## 3 · How the pieces fit

### 3.1 Scene timing (all values in whole frames)

For scenes `i = 0…n−1` with start `sᵢ`, end `eᵢ`, duration `dᵢ` and incoming transition `trᵢ`
(`tr₀ = 0`), as computed by `sceneTimes()` in `engine/scripts/lib/hf.mjs` and by `VM.start`:
the overlap of scenes `i−1` and `i` is `[sᵢ, eᵢ₋₁)`, of length `trᵢ`.

| Track | Item | Timeline range | Media |
|---|---|---|---|
| V1 | scene `i` | `[sᵢ, sᵢ₊₁)` (last scene: `[sₙ₋₁, eₙ₋₁)`) | solo render of scene `i`, local `0…dᵢ`, padded by `H` held frames each side; source range starts at `H` |
| V2 | transition `i−1 → i` | `[sᵢ, eᵢ₋₁)` | the full composition over that window, overlays off |
| V3 | captions / overlays | `[0, T)` | overlay layer only, transparent background |
| A1 | voice for scene `i` | the narration's span in `timing.json` | cut from the voice track |
| A2 | music | `[0, T)` | the ducked music bed |
| A3 | sfx cue | cue time … + length | the cue with its gain applied |
| A4 | mastered mix | `[0, T)`, track disabled | `mix.wav` |

V2 fully covers every overlap, so the solo scene's missing transition animation is never visible.
If the editor deletes a V2 clip they get a hard cut. The handles let them add their own dissolve
or slide the cut.

All boundaries must land on whole frames, or clips drift when they are joined (step A2).

### 3.2 Solo and layer modes (runtime)

- `?solo=<id>`: build only that scene, as a cut (no transition), with overlays off, starting at local time 0.
- `?layer=scenes`: the full composition with overlays hidden (used for transition clips).
- `?layer=overlays`: scenes hidden and the page background transparent (used for the caption layer).

A solo build must produce exactly the same pixels as that scene inside the full composition
(outside transition windows). QA gate 3c checks this (step A3).

### 3.3 Cache fingerprint

Scene `i` is re-rendered only when its fingerprint changes. The fingerprint is the SHA-1 of:
- `scenes/<id>.js`;
- the scene's storyboard entry after retiming (duration, beats, visual, data);
- `storyboard.style`, `canvas`, `assets.scripts` and the contents of those scripts;
- `style.css`, `index.html` and `lib/**`;
- the files under `assets/` that the scene's code or storyboard entry names;
- a hash of `engine/runtime/**`, the fps, the edit codec and the handle length.

A transition's fingerprint combines both neighbours' fingerprints with the transition spec. The
caption layer's fingerprint covers `captions.json`, `style`, `overlays` and the runtime hash.
When unsure, include an input: a spurious re-render is cheap, a stale clip is a bug.
Escape hatches: `--force` and `--only <id>`.

### 3.4 Final export from `edit/`

The picture is a plain sequence: `body₀[0, s₁) · trans₁ · body₁[tr₁ …] · trans₂ · …`, where each
body is trimmed to the part not covered by a transition. The captions layer is overlaid in one
pass, then `mix.wav` is muxed and the result encoded to H.264 (or H.265 / WebM). No browser is
involved, so a re-export after an edit takes seconds.

### 3.5 Conversions

Node writes the `.otio` JSON itself (no dependency). The other formats go through Python's
`opentimelineio` and its adapters, installed once into `~/venvs/otio` by
`engine/timeline/setup.sh` (or `setup.ps1`). After every conversion the file is read back and
compared with the `.otio`, and anything the format dropped is printed.

| `--to` | Writes | Keeps | Loses / caveat |
|---|---|---|---|
| (default) `resolve` `premiere` `kdenlive` `avid` `blender` | `<slug>.otio` | everything | Premiere's OTIO import is recent; older versions use `premiere-legacy` |
| `bundle` | `<slug>.otioz` (timeline + media, relative paths) | everything | large file; for moving to another machine |
| `finalcut` | `<slug>.fcpxml` | tracks, markers | V2/V3 become connected clips |
| `shotcut` | `<slug>.mlt` | tracks, audio, alpha | markers partial |
| `openshot` | `<slug>.xml` (FCP7) | tracks, audio | markers |
| `lightworks` | `<slug>.xml` (FCP7) | tracks, audio | — |
| `premiere-legacy` | `<slug>.xml` (FCP7) | tracks, audio, markers | — |
| `avid-aaf` | `<slug>.aaf` | tracks, audio | heaviest dependency |
| `edl` | `<slug>.edl` | the V1 cut list | one video track only; last resort |

FCP7 XML and FCPXML need absolute media paths, so they are written for the current machine: on
another machine, re-run the conversion or relink media in the editor. OTIO, OTIOZ and MLT keep
relative paths.

## 7 · Risks

| Risk | Mitigation |
|---|---|
| A scene depends on another scene's state, so solo ≠ full | gate 3c fails loudly; fix the scene (usually shared DOM or a global) |
| Relative `target_url` not honoured by an editor | `--absolute`, or `--to bundle` (`.otioz`) |
| Premiere's OTIO import is still maturing | `premiere-legacy` (FCP7 XML) is always available |
| Large ProRes files | `--edit-codec h264i`; `.build/` and `edit/` are git-ignored |
| No maintained MLT adapter | own writer (E3.4); MLT XML is small and documented |
| An editor caches old media after a clip is replaced | `references/editing.md` gives the refresh/relink step per editor |
| Reseeding `Math.random` changes existing videos | one-time change, stated in the A2 commit; re-render affected projects when they are next touched |
